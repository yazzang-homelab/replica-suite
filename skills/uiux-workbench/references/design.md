# 설계·상태 계약

현재 화면·데이터·플랫폼을 확인한 뒤 필요한 항목을 적용한다. 이 문서는 모든 앱에 같은 시안·화면 수를 강제하지 않는다.

| 결정 | 관찰하거나 정할 내용 | 구현 뒤 확인 |
|---|---|---|
| 사용자와 작업 | 역할, 가장 자주 하는 작업, 중단 시 손실 | 실제 데이터로 핵심 작업 완료 |
| 정보 위계 | 현재 위치·대상·작업 결과, 한 화면의 주된 행동 | 선택 상태·처리 상태를 구별 가능 |
| 동선 | 선택→편집→저장/출력, 취소·되돌리기 | 마우스와 키보드로 같은 결과 |
| 상태 | 해당 제품의 초기·빈·로딩·오류·성공·충돌 | 사용자에게 원인·다음 행동 제시 |
| 디자인 토큰 | 역할별 색상·글꼴·간격·모서리, 기존 정체성 | 의미가 같은 요소에 일관되게 적용 |
| 반응형 | 좁은 폭·배율·긴 번역·실제 문장 | 잘림·숨은 버튼·가로 넘침 확인 |
| 접근성 | 이름·역할·대비·순서·키보드·동작 줄이기 | 자동 검사와 직접 조작을 나눠 기록 |

수동 확인이 필요한 예: 모달 포커스 진입·복원, 위험 작업의 취소/복구, 화면 읽기 순서, 실제 장비 글꼴·DPI·다중 모니터. 자동검사의 검출 범위를 넘는 항목은 확인하지 않은 채 통과로 쓰지 않는다.

설계 산출물은 대상 프로젝트의 기존 문서에 기록한다. 새 문서가 필요한 경우 사용자·핵심 작업·상태·토큰·검사 연결을 한곳에 유지하고 실행 계약의 flow_id와 연결한다. 상태 제목만 나열한 문서가 상태별 실제 실행을 증명하지는 않는다.

참고 서비스의 외형을 따르는 요청은 관측한 치수와 추정한 값을 구분한다. 색상 취향, 유행하는 레이아웃, 임의의 'AI 디자인 패턴'만으로 품질 판정을 내리지 않는다. 원본 픽셀 비교가 필요하면 [shot-compare-iterate](../../shot-compare-iterate/SKILL.md) 또는 [web-verify-pixel](../../web-verify-pixel/SKILL.md)를 사용한다.
